# Can the camera HAL be compiled for our Redroid image (and can v4l2loopback replace Cuttlefish)?

**Verdict: feasible with a from-source rebuild (confidence: medium-high for camera capture/scan, low-medium for on-screen preview, low for mic).** Nothing exists that lets the stock `redroid/redroid:11.0.0-latest` image take a camera: upstream Redroid still ships no camera provider at all (open issue #916, Feb 2026), and every "copy libs in" attempt in the issue tracker died on exactly the VNDK/linker failures in our notes. But in Sept 2026 a third party (fancyCachier/droidpool) published a complete, end-to-end verified recipe for AOSP's **External Camera Provider** on a self-built Redroid **14** arm64 image fed by `ffmpeg -> v4l2loopback` (RTSP, trivially RTMP). It needed seven non-obvious fixes (HAL, gralloc, media_profiles, v4l2loopback params) that nobody had found before, which is why earlier attempts failed. The same approach ports to Android 11 (the HIDL `@2.4-external-service` in the `android-11.0.0_r48` tree Redroid 11 is built from), but no one has published that port. Two things keep Cuttlefish necessary for now: droidpool reports live on-screen preview needs a hardware GPU (we have none on OCI A1; JPEG capture and YUV frame analysis work), and Redroid has no mic path at all without a second HAL build.

## Which Redroid version/fork to try first

**Recommendation: Redroid 14 (`redroid-14.0.0_r2` manifest) + droidpool's `apply-*.sh`, built with Redroid's own builder, as the first experiment; port to 11 only if the 14 move is unacceptable.** Reasons: it is the only published, verified camera recipe on any Redroid; it uses the AIDL provider (droidpool found the HIDL `@2.7` module silently produces no binary on 14); scripts are idempotent and small (+179/+488 lines); 14 has MindTheGapps `14.0.0-arm64` and better app compatibility; images run privileged/arm64/ADB like today. Costs: re-validate our automation on 14, and droidpool is archived. Porting to **11** is plausible (same provider logic; `kMaxBytesPerPixel = 2` and lazy per-frame `mmap` are present in the r48 3.4 code; the 3.5+ `BufferRequestThread` race does not apply when `hal3TrebleMinorVersion` stays at its default 4; HIDL manifest entry `android.hardware.camera.provider 2.4 ICameraProvider external/0`), but no one has done it, so budget a second debug cycle. **Not recommended:** Waydroid (LXC + Wayland compositor, external HAL currently reporting 0 devices in 2026, mic path undocumented), budtmo/docker-android (QEMU emulator = same class as Cuttlefish), Android 15/16 virtual camera (needs a privileged companion-role system app and a feed app; no Redroid recipe). `redroid-modules` is only the binder/ashmem kernel modules repo, not a fork.

## Minimal experiment (one Redroid 14 container on an A1.Flex VM)

1. Build host (x86_64, 64 GB RAM, 400 GB): `repo init -u https://github.com/remote-android/platform_manifests.git -b redroid-14.0.0_r2`, sync, run droidpool `apply-camera.sh`, `apply-camera-hal-fix.sh`, `apply-gralloc-camera-fix.sh` (paths `$SRC/hardware/interfaces/camera/device/default`, `vendor/redroid/gralloc`), `lunch redroid_arm64-userdebug`, `m`, then `mkimg.sh`/`tar --xattrs | docker import --platform linux/arm64`. Keep `fpsBound="30.0"` for 720p in `external_camera_config.xml` unless you run `v4l2loopback-ctl set-fps`.
2. OCI host: `apt install v4l2loopback-dkms v4l2loopback-utils`; `modprobe v4l2loopback devices=1 video_nr=21 card_label=cam exclusive_caps=0 max_buffers=8`; `modprobe snd-aloop` (for later mic work).
3. Feed: `ffmpeg -listen 1 -i rtmp://0.0.0.0/live/key -an -vf scale=1280:720 -r 15 -c:v mjpeg -q:v 5 -f v4l2 /dev/video21` (landscape only; MJPEG only).
4. Run: add `--device /dev/video21` and `-v cam-config.xml:/vendor/etc/external_camera_config.xml:ro` (with `<ignore>` of every other host `/dev/video*`) to the existing privileged `docker run`.
5. After the feed is up: `docker exec <c> sh -c 'chmod 0666 /dev/video21; setprop ctl.restart vendor.camera.provider-ext'` (on 11: `vendor.camera-provider-2-4-ext`).
6. Check: `adb shell dumpsys media.camera | grep -A3 "Number of camera devices"` expecting 1 and `device@1.x/external/21`; `logcat -s ExtCamPrvdr ExtCamDev ExtCamDevSsn`; then a QR-scan app (CameraX ImageAnalysis), the stock camera's shutter (JPEG), and a Chrome `getUserMedia` page to test **preview**.
7. Mic (separate step): pass `--device /dev/snd`, build the goldfish tinyalsa HAL pointed at the Loopback card, write with `ffmpeg -i rtmp://… -vn -f alsa hw:Loopback,0,0`.

## Risks / what still keeps Cuttlefish necessary

- **Preview:** droidpool states live preview fails under software GL (SwiftShader) and needs a hardware GPU; OCI A1 has none. If calls/KYC flows need a visible viewfinder, Cuttlefish stays until this is solved (gralloc/EGL YUV support) — test step 6 decides.
- **Mic:** zero published Redroid mic solutions (#548, #857); requires a second from-source HAL and audio-policy work. Until then Cuttlefish remains the only mic path.
- **Format/orientation:** HAL is MJPEG-only, landscape-only, discrete sizes; the front/back camera appear as one `EXTERNAL` camera (`LENS_FACING_EXTERNAL`), which some apps ignore.
- **Ops:** `--privileged` exposes all host nodes (per-device ignore lists required); HAL must be restarted after a feed (re)starts; ~0.7 core per 720p15 feed; maintainer offers no support; droidpool is archived; Android 11 port is unproven and its provider binary is 32-bit.
